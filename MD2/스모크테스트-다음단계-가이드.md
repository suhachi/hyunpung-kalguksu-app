## 🎯 다음 단계 (순서대로)

### 1단계: 브라우저에서 실제 테스트 수행

**개발 서버**: `http://localhost:3001` (이미 실행 중)

#### 테스트 체크리스트 (6개 항목)

##### A. 로그인 성공 → /admin 접근 확인
1. 브라우저에서 `http://localhost:3001/login` 접속
2. 로그인 정보 입력:
   - 이메일: `admin@hp-kal.com`
   - 비밀번호: (설정된 비밀번호)
3. 로그인 버튼 클릭
4. **확인 사항**:
   - [ ] 로그인 성공 토스트 노출
   - [ ] `/admin` 경로로 자동 리다이렉트
   - [ ] 관리자 대시보드 정상 표시
   - [ ] 상단 바에 사용자 이메일 및 role 표시

##### B. 메뉴 이미지 업로드 (신규 생성)
1. `/admin/menus` 접속
2. 신규 메뉴 생성 또는 기존 메뉴 수정 클릭
3. 이미지 파일 선택 (JPG/PNG 등)
4. 개발자 도구 → Network 탭 열기
5. 저장 버튼 클릭
6. **확인 사항**:
   - [ ] `OPTIONS` 요청 → 상태 코드 `200 OK`
   - [ ] `PUT` 요청 → 상태 코드 `200 OK`
   - [ ] Firebase Console → Storage → `menus/{menuId}/{timestamp}.webp` 경로 생성 확인

##### C. 기존 이미지 교체
1. 이미지가 있는 기존 메뉴 선택
2. "수정" 버튼 클릭
3. 새 이미지 파일 선택
4. 개발자 도구 → Console 탭 열기
5. 저장 버튼 클릭
6. **확인 사항**:
   - [ ] 콘솔에 "기존 이미지 삭제 실패" 경고 없음 (또는 정상 삭제 로그)
   - [ ] Firebase Console에서 이전 파일 삭제 확인
   - [ ] 새 파일 생성 확인 (`{timestamp}.webp` 형식)

##### D. UI 토스트/로딩 정상
1. 이미지 업로드 중 상태 확인
2. **확인 사항**:
   - [ ] 저장 버튼 "저장 중..." 텍스트 표시
   - [ ] 저장 버튼 disabled 상태
   - [ ] 저장 완료 시 "저장 완료" 토스트 노출
   - [ ] 에러 발생 시 에러 메시지 토스트 노출

##### E. CORS 확인
1. 개발자 도구 → Network 탭 확인
2. OPTIONS 요청 선택
3. **확인 사항**:
   - [ ] Response Headers에 `Access-Control-Allow-Origin` 포함
   - [ ] 값이 `http://localhost:3000` 또는 `http://localhost:5173`
   - [ ] CORS 에러 없음 (콘솔에 CORS 관련 에러 없음)

##### F. 회귀 테스트
1. 위 시나리오(A~E) 전체를 1회 재수행
2. **확인 사항**:
   - [ ] 모든 기능 정상 작동
   - [ ] 캐시 영향 없음

## 🚨 테스트 실패 시 대응

### `storage/unauthorized` 에러
- **조치**: Firebase Console → Firestore → `users/{uid}.role` 확인 및 수정
- **재시도**: 재로그인 후 다시 테스트

### Preflight (OPTIONS) 실패
- **조치**: 
  ```bash
  gsutil cors set cors.json gs://hp-kal.firebasestorage.app
  gsutil cors get gs://hp-kal.firebasestorage.app  # 확인
  ```
- **재시도**: 브라우저 새로고침 후 다시 테스트

### 버킷 불일치
- **조치**: `.env` 파일에서 `VITE_FIREBASE_STORAGE_BUCKET=hp-kal.firebasestorage.app` 확인
- **재시도**: 개발 서버 재시작 후 다시 테스트
