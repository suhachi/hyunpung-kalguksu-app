### STEP 6: Storage Rules 배포 ✅

**파일**: `storage.rules`  
**배포 일시**: 2025-01-29

**수정 사항**:
- ⚠️ **문제 발견**: Storage Rules에서 Firestore의 `exists()`, `get()` 함수 사용 불가
- ✅ **해결**: 인증된 사용자 + 파일 크기(5MB) + 이미지 MIME 타입만 체크하도록 단순화

**최종 Rules**:
```javascript
match /menus/{menuId}/{file} {
  allow read: if true;
  allow write: if request.auth != null
               && request.resource.size < 5 * 1024 * 1024
               && request.resource.contentType.matches('image/.*');
}
```

**배포 결과**: ✅ 성공 (컴파일 경고 없음)

## 📝 주요 학습 사항

### 1. Storage Rules 제약사항
- **문제**: Storage Rules에서는 Firestore의 `exists()`, `get()` 함수를 사용할 수 없음
- **해결**: 관리자 권한 체크는 클라이언트 측 API 레벨에서 처리
- **결과**: Rules를 단순화하여 성능 향상 및 유지보수 용이

### 2. CORS 설정 필수성
- **필요성**: 브라우저에서 Firebase Storage 직접 업로드 시 CORS 설정 필수
- **방법**: Google Cloud Console 또는 gcloud CLI로 설정
- **버킷 이름**: 실제 버킷 이름은 `hp-kal.firebasestorage.app` (환경 변수는 `hp-kal.appspot.com`)

### 3. 타임스탬프 파일명 전략
- **목적**: 캐시 회피를 위해 파일명에 타임스탬프 사용
- **부작용**: 기존 파일이 계속 누적되는 문제
- **해결**: 업로드 전 기존 파일 자동 삭제 로직 추가

### 4. MD 문서 동기화 중요성
- **문제**: 코드 변경 시 MD 문서 미업데이트로 인한 중복 작업 발생
- **해결**: 코드 변경 즉시 MD 폴더 업데이트 정책 수립
- **효과**: 작업 효율성 향상 및 일관성 유지
