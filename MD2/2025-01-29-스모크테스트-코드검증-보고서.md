if (imageFile) {
  // 기존 이미지 URL에서 파일명 추출하여 삭제

    const oldFileName = extractFileNameFromUrl(menu.image);
    if (oldFileName) {
      try {
        await deleteMenuImage(menu.menuId, oldFileName);
      } catch (e) {
        // 삭제 실패해도 업로드는 계속 진행

### F. Storage Rules ✅

#### 파일: `storage.rules`
```javascript
match /menus/{menuId}/{file} {
  allow read: if true;
  allow write: if request.auth != null
               && request.resource.size < 5 * 1024 * 1024
               && request.resource.contentType.matches('image/.*');
}
```

**검증 결과**:
- ✅ 인증된 사용자만 쓰기 허용 (`request.auth != null`)
- ✅ 파일 크기 제한: 5MB
- ✅ MIME 타입 제한: `image/*`
- ✅ **주의**: Storage Rules는 Firestore `exists/get` 함수를 지원하지 않으므로, role 체크는 클라이언트에서 처리 (RequireAdmin HOC)

## 🚨 잠재적 문제점 및 대응 방안

### 1. CORS 미적용 가능성
**증상**: OPTIONS 요청 실패  
**원인**: CORS 설정이 버킷에 적용되지 않았을 수 있음  
**조치**:
```bash
gsutil cors set cors.json gs://hp-kal.firebasestorage.app
gsutil cors get gs://hp-kal.firebasestorage.app
```

### 2. Firestore role 불일치
**증상**: `storage/unauthorized` 에러  
**원인**: `users/{uid}.role`이 `owner` 또는 `admin`이 아님  
**조치**: Firebase Console에서 `role` 필드 확인 및 수정

### 3. 버킷 이름 불일치
**증상**: 업로드 실패 또는 다른 버킷에 업로드  
**원인**: `.env` 파일의 `VITE_FIREBASE_STORAGE_BUCKET` 값 오류  
**조치**: `hp-kal.firebasestorage.app` 확인 및 개발 서버 재시작

### 4. AdminLayout 토스트 중복
**상태**: ✅ 이미 해결됨  
**조치**: 중복 권한 체크 제거 완료
