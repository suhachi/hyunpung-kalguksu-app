## 📋 작업 개요

### 목표
마이페이지(`/my`)에 로그인 시스템을 통합하여, 로그인하지 않은 사용자도 마이페이지에서 직접 로그인할 수 있도록 구현

### 배경
- 기존 로그인 페이지는 `/login` 경로에 별도로 구현되어 있음 ✅
- 마이페이지는 로그인 없이 접근 가능하지만, 로그인 상태에 따른 UI 차별화 필요
- 사용자 경험 개선: 마이페이지에서 바로 로그인 가능하도록

---

## ✅ 구현 완료 내역

### 1. 로그인 상태 확인 ✅
- **파일**: `src/pages/app/My.tsx`
- **구현**: `useCurrentUser()` 훅을 사용하여 현재 로그인 상태 확인
- **결과**: 로그인 여부에 따라 UI 분기 처리

### 2. 로그인되지 않은 경우 UI ✅
**표시되는 요소**:
- 로그인 안내 카드
- "여기서 로그인" 버튼 (인라인 로그인 폼 토글)
- "로그인 페이지로 이동" 버튼 (`/login` 이동)
- 로그인 후 이용 가능한 서비스 안내

**인라인 로그인 폼**:
- 이메일 입력 필드
- 비밀번호 입력 필드
- 로그인 버튼 (로딩 상태 표시)
- 취소 버튼

### 3. 로그인된 경우 UI ✅
**표시되는 요소**:
- 사용자 정보 카드 (이메일, 역할 표시)
- 역할 배지 (고객/관리자 구분)
- 누적 주문 수 표시
- 로그아웃 버튼
- 기존 빠른 메뉴 그리드 (주문내역, 쿠폰함, 포인트 등)

### 4. 로그인 기능 ✅
- **함수**: `handleLogin()` - Firebase Auth 로그인
- **에러 처리**: `toast.error()`로 에러 메시지 표시
- **성공 처리**: `toast.success()` 후 로그인 폼 닫기

### 5. 로그아웃 기능 ✅
- **함수**: `handleLogout()` - Firebase Auth 로그아웃
- **리다이렉트**: 로그아웃 후 홈(`/`)으로 이동
- **에러 처리**: 실패 시 토스트 메시지 표시

## 🎨 UI/UX 개선 사항

### 로그인되지 않은 경우
1. **로그인 안내 카드**
   - 눈에 띄는 아이콘 및 메시지
   - 명확한 행동 유도 (버튼 2개 제공)

2. **인라인 로그인 폼**
   - 페이지 이동 없이 로그인 가능
   - 로딩 상태 표시
   - 에러 메시지 표시

3. **대안 제공**
   - 인라인 로그인
   - 로그인 페이지로 이동
   - 두 가지 선택지 제공

### 로그인된 경우
1. **사용자 정보 표시**
   - 이메일 기반 사용자명 표시
   - 역할 배지 (고객/관리자 구분)
   - 누적 주문 수 표시

2. **로그아웃 버튼**
   - 명확한 위치 (사용자 정보 카드 하단)
   - 아이콘과 함께 표시
