### 1. tsconfig.json 문제

#### 보고서 주장
```
❌ "루트에 tsconfig.json이 없음"
```

#### 실제 상황 (현재 파일 구조)
```
✅ tsconfig.json - 루트에 존재
✅ tsconfig.node.json - 루트에 존재
✅ functions/tsconfig.json - 존재
```

#### 불일치 원인 추정
```
가설 1: 초기 버전에는 실제로 없었음
가설 2: "15-미리보기-문제-진단-및-해결.md"에서 
        "누락된 Vite 프로젝트 진입점 파일들을 생성"했다고 기록됨
        → tsconfig.json도 이때 생성된 것으로 추정
```

**증거 문서**:
```
/docs/03-development/15-미리보기-문제-진단-및-해결.md:
"누락된 Vite 프로젝트 진입점 파일들(index.html, main.tsx, 
package.json, vite.config.ts, tsconfig.json 등 9개 파일)을 
모두 생성하여 미리보기가 정상 작동하도록 완료"
```

**결론**: tsconfig.json은 **최근에 생성**되었으며, 보고서는 **생성 이전 상태**를 분석

### 2. package.json 버전 "*" 문제

#### 보고서 주장
```
❌ "모든 의존성이 '*' 버전"
```

#### 실제 상황
```json
{
  "dependencies": {
    "react": "^18.2.0",
    "react-router-dom": "^6.22.0",
    ...
  }
}
```

#### 불일치 원인 분석

**가설 1: 초기 Figma Make 생성 버전**
```
Figma Make가 초기 생성 시:
"dependencies": {
  "react": "*",
  "firebase": "*"
}

이후 수동으로 버전 명시로 변경
```

**가설 2: Functions 폴더 혼동**
```
/functions/package.json 확인 결과:
✅ 모든 버전이 명시되어 있음
→ 이 가설도 맞지 않음
```

**가설 3: 문서 내용 혼동**
```
/docs/ 폴더의 기획서에서 예시로 든 코드:
"dependencies": {
  "firebase": "*",
  ...
}

→ 문서의 예시 코드를 실제 코드로 착각?
```

**결론**: 보고서가 **문서의 예시 코드** 또는 **매우 오래된 버전**을 분석

### 3. tailwind.config.js 위치 문제

#### 보고서 주장
```
❌ "src/tailwind.config.js에 있음"
```

#### 실제 파일 구조
```
✅ /tailwind.config.js (루트)
❌ /src/tailwind.config.js (없음)
```

#### 불일치 원인 분석

**파일 구조 확인**:
```
현재 프로젝트 구조:
/ (루트)
├── tailwind.config.js ✅
├── components/
├── pages/
├── lib/
├── styles/
└── (src/ 폴더 자체가 없음!)
```

**중요한 발견**:
```
이 프로젝트는 src/ 폴더를 사용하지 않음!
→ 모든 소스 코드가 루트에 직접 위치
→ components/, pages/, lib/ 등이 루트에 있음
```

**보고서 작성자의 착각 추정**:
```
일반적인 Vite 프로젝트 구조:
/
├── src/
│   ├── components/
│   ├── pages/
│   └── tailwind.config.js ❌

하지만 이 프로젝트:
/
├── components/
├── pages/
└── tailwind.config.js ✅
```

**결론**: 보고서 작성자가 **일반적인 프로젝트 구조를 가정**하고 작성

### 5. Vite Config "20개 alias" 문제

#### 보고서 주장
```
❌ "20개 이상의 alias 설정으로 복잡함"
```

#### 실제 vite.config.ts
```typescript
export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './'),  // 단 1개!
    },
  },
  ...
});
```

#### 불일치 원인 분석

**가설: 이전 버전에 실제로 있었던 복잡한 설정**
```typescript
// 추정되는 이전 버전
resolve: {
  alias: {
    '@radix-ui/react-slot@1.1.2': '@radix-ui/react-slot',
    'sonner@2.0.3': 'sonner',
    'recharts@2.15.2': 'recharts',
    // ... 20개
  }
}
```

**증거**: import @version 문제와 연관
```typescript
현재 코드에:
import { Slot } from "@radix-ui/react-slot@1.1.2";

→ 초기에는 이를 해결하기 위해 
  vite.config.ts에 alias를 20개 추가했을 가능성
  
→ 이후 alias는 제거했지만
  import 구문은 아직 수정 안 됨
```

**결론**: 보고서는 **중간 과도기 버전**을 분석했을 가능성
